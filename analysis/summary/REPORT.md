### Reko patterns the mechanical rules did not anticipate

1. Definition signatures differ from the comment signatures: Reko drops the
   `Register`/`Stack`/`Sequence` storage classes and spells an output
   parameter `TYPE & name`.  The converter parses the *definition* signature.
2. `Sequence`/`FlagGroup` are collapsed in the definition signature
   (`Sequence segptr32`->`segptr32`, `Sequence ptr32`->`ptr32`,
   `Sequence word32`/`ui32`->`word32`/`ui32`, `FlagGroup bool`->`bool`), so
   the multi-register return information must be recovered from the union
   width / member names.
3. `struct Eq_N &` output parameters are already pointers; appending `*`
   would wrongly yield `void **`.  The output-append rule therefore applies
   only to scalar outputs.
4. `mp16` is a ds-relative 16-bit offset, not a pointer, and the `Eq_526`
   union (used for the `bp`-style frame offsets) mixes a `uint8` member with
   member pointers: it is a 16-bit offset, mapped to `u16` (so `Eq_526 &`
   outputs become `u16 *`).
5. `(ptr16 Eq_N)` / `(ptr32 Eq_N)` pointees become opaque `void *` (matching
   `src/prototypes.h`), while a bare `Eq_N *` pointee becomes `u8 *`; this
   distinction is needed for the prototypes.h identity check.
